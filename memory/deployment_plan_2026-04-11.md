# План развертывания сервера игры + CRM + Telegram (2026-04-11)

Ниже план по шагам, варианты VPS и доменных регистраторов, а также перечень потенциальных недостающих частей проекта.

## 1) Подготовка и выбор инфраструктуры

1. Определить нагрузку и минимальные требования.
   - Сколько одновременных игроков, ожидаемый RPS на API, размер БД, требования к задержке.
   - Минимальный старт: 1–2 vCPU, 2–4 GB RAM, SSD 25–50 GB.  
2. Выбрать провайдера VPS (варианты ниже) и регион ближе к аудитории.
3. Выбрать регистратор домена (варианты ниже).

## 2) Домен и DNS

1. Купить домен у регистратора.
2. Включить DNS-хостинг (можно у регистратора или у Cloudflare).
3. Завести DNS-записи:
   - `A` запись на публичный IP VPS для `api.<domain>` и `app.<domain>` (или корневого домена).
   - (Опционально) `AAAA` для IPv6, если включен.
4. Включить HTTPS (обычно через автоматический сертификат от Let’s Encrypt в прокси).

## 3) Виртуальная машина

1. Создать VPS (Ubuntu 22.04 LTS или 24.04 LTS).
2. Настроить доступ:
   - только SSH-ключи
   - отключить парольный вход
   - поменять дефолтный порт (опционально)
3. Базовая безопасность:
   - включить `ufw`/firewalld
   - открыть только нужные порты: `80`, `443`, `22`
4. Установить Docker и Docker Compose.

## 4) Контейнеры и окружение

1. Подготовить `docker-compose.yml` (игра, CRM, БД, Redis, reverse-proxy).
2. Подготовить `.env` для прод окружения (секреты, токены, URL-ы).
3. Запустить:
   - `docker compose up -d`
4. Проверить healthcheck, логи, метрики.

## 5) Reverse-proxy и HTTPS

1. Выбрать прокси: Nginx / Caddy / Traefik.
2. Настроить TLS и автообновление сертификатов.
3. Проксировать маршруты:
   - `api.<domain>` → backend API
   - `app.<domain>` → фронтенд/mini-app
   - `crm.<domain>` → CRM

## 6) Telegram Bot и Webhook

1. Создать/подготовить бота в @BotFather.
2. Настроить Webhook:  
   - URL вида `https://api.<domain>/telegram/webhook/<secret>`  
   - Вызвать `setWebhook` (официальный Bot API).  
3. Проверить `getWebhookInfo` и логи доставки.
4. Включить проверку `X-Telegram-Bot-Api-Secret-Token` на своей стороне.

## 7) Запуск игры в Telegram

1. Использовать Telegram Mini Apps (Web Apps) и фронтенд `app.<domain>`.
2. Для авторизации использовать `initData`/`hash` от Telegram Web Apps (серверная проверка).
3. Запуск из бота:
   - Кнопка меню (`setChatMenuButton`) или inline-кнопка `web_app` с URL.
4. Для login-widget (если используете веб-виджет): привязать домен командой `/setdomain` в @BotFather.

## 8) Мониторинг, бэкапы, доступы

1. Бэкапы БД (ежедневно) + резервные снапшоты VPS.
2. Мониторинг: CPU/RAM/Disk, аптайм, ошибки 5xx.
3. Логи в централизованное хранилище (или хотя бы ротация).
4. Отдельные доступы для команды (SSH ключи по пользователям).

## 9) Релизы и эксплуатация

1. CI/CD (GitHub Actions/GitLab CI) для сборки и деплоя.
2. Канареечный/стейджинг сервер (желательно).
3. Процедура отката (rollback) и регламент инцидентов.

# Варианты VPS (актуальные прайсы и официальные страницы)

1. DigitalOcean Droplets (простая панель, удобная для старта).  
2. Linode (Akamai Cloud) Shared CPU (хороший баланс цена/ресурсы).  
3. Vultr Cloud Compute (много регионов, предсказуемая цена).  
4. AWS Lightsail (простые бандлы, интеграция с AWS).  
5. OVHcloud VPS (доступно в ЕС, есть анти-DDoS).

---

# Варианты доменного регистратора

1. Cloudflare Registrar (at-cost, бесплатный DNS и DNSSEC).  
2. Squarespace Domains (после миграции Google Domains).

---

# Что еще может не хватать проекту

1. **Юридические документы**: политика конфиденциальности, оферта, обработка персональных данных (особенно если EU).
2. **Согласие на обработку данных Telegram** и хранилища user_id/username.
3. **Rate limiting и анти-бот защита** (на API и webhook).
4. **Observability**: метрики, алерты, трассировка.
5. **Очереди/фоновая обработка** (если есть тяжелые задачи).
6. **План масштабирования** (БД, кеш, горизонтальное масштабирование).
7. **Финансовые/платежные интеграции** (если монетизация).
8. **SLO/аптайм, SLA** и регламент инцидентов.
9. **Стейджинг среда** для безопасных релизов.
10. **План миграции/бэкап-стратегия** (RPO/RTO).
