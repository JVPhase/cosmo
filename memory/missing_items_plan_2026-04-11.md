# План реализации недостающих элементов (отсортировано по критичности)

Дата: 2026-04-11

## Критично (P0)

### 1) Юридические документы (privacy policy, оферта/terms, DPA/обработка ПД)
**Почему критично:** Без этого высокий юридический риск и блокировка партнеров/платежей, особенно при работе с EU.

**Что сделать:**
1. Составить перечень персональных данных (user_id, username, Telegram IDs, IP, платежные данные, логи).
2. Определить роли: оператор/процессор, страны обработки, субпроцессоры.
3. Подготовить документы: Privacy Policy, Terms/Offer, Consent for Telegram data, DPA/Политика обработки ПД.
4. Добавить ссылки в UI/бот и чекбоксы согласия при сборе данных.
5. Настроить хранение согласий (кто/когда/версия документа).

**Готовый результат:** Документы в `docs/legal/*`, ссылки в продукте, хранение согласий в БД.

**Промпт для Claude Code:**
```
Проект: Telegram miniapp + сервер.
Нужно: создать пакет юридических документов и внедрить их в продукт.
Сделай:
1) черновики документов: Privacy Policy, Terms/Offer, Consent for Telegram data, DPA/Политика обработки ПД (RU+EN если возможно).
2) файл `docs/legal/README.md` с перечнем данных, ролями, субпроцессорами, сроками хранения.
3) план интеграции в UI и бота (где показываем ссылки, где чекбоксы).
4) предложи структуру таблицы `user_consents` и API для записи согласий.
Выведи итоговые файлы и список TODO.
```

### 2) Rate limiting и анти-бот защита (API и webhook)
**Почему критично:** Защищает от злоупотреблений, ботов, DDoS и финансовых потерь.

**Что сделать:**
1. Ввести лимиты на IP, user_id, Telegram chat/user ID и на webhook source.
2. Добавить серые/черные списки и динамическое усиление лимитов.
3. Валидация подписи/секретов webhook (если поддерживается).
4. Интегрировать защиту на уровне reverse proxy и приложения.

**Готовый результат:** Единый middleware, конфиг лимитов, метрики блокировок.

**Промпт для Claude Code:**
```
Проект: Node/TS сервер. 
Нужно: добавить rate limiting + anti-bot для API и webhook.
Сделай:
1) middleware для rate limiting (IP + user_id + telegram user/chat id).
2) конфиг лимитов по маршрутам и окружениям.
3) блокировку/капчу или "slow down" при превышении.
4) логирование и метрики по блокировкам.
5) примеры тестов.
Покажи, какие файлы и где поменять.
```

## Высокая критичность (P1)

### 3) Observability: метрики, алерты, трассировка
**Почему важно:** Без наблюдаемости сложно быстро реагировать на инциденты.

**Что сделать:**
1. Внедрить метрики (latency, error rate, queue depth, webhook failure).
2. Логи с корреляцией (trace_id, user_id).
3. Трассировка основных потоков (login, purchase, webhook).
4. Алерты по SLO.

**Готовый результат:** Дашборды + алерты + трассировка.

**Промпт для Claude Code:**
```
Проект: Node/TS сервер.

4) документацию: какие метрики, какие алерты.
Покажи изменения в коде и пример dashboard/alert config.
```

3. Проверить восстановление (disaster recovery test).
