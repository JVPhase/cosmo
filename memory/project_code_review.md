# Обзор проекта: потенциально слабые места

Стек: Expo/React Native (`mobile/cosmo-miner`), Fastify 5 + Prisma + PostgreSQL (`server`), общий пакет `@cosmo/game-config`.

Дата фиксации: 2026-04-04.

---

## Сильные стороны (кратко)

- Аутентификация: Argon2, защита от перечисления пользователей при логине через `dummyHash`, ротация refresh-токенов, rate limit на чувствительных эндпоинтах.
- Сейвы: оптимистичная конкуренция по `rev`, понятный контракт 409.
- Remote config: сервер отдаёт `/config` из общего пакета — хорошая основа для подстройки баланса без релиза клиента.

---

## Критичные / высокий приоритет

### 1. Расхождение документации и реализации JWT

В `memory/project_auth_and_saves.md` указано «JWT RS256», а `server/src/plugins/jwt.ts` использует симметричный `JWT_SECRET` с `@fastify/jwt` — обычно это **HS256**, не RS256. Путает при аудите и интеграции.

**Файлы:** `server/src/plugins/jwt.ts`, `memory/project_auth_and_saves.md`.

### 2. Облако: после выбора более свежего сейва с сервера не обновляется локальный `rev`

`storeCloudRev` вызывается только из `pushCloudSave` после успешного PUT. При старте, если клиент берёт облако (`fetchCloudSave`), **ревизия с сервера не записывается в AsyncStorage**. Автосейв затем шлёт устаревший `rev` → **409**, а в `App.tsx` конфликт **тихо игнорируется** — облачная синхронизация может остановиться.

**Файлы:** `mobile/cosmo-miner/src/game/cloudSave.ts`, `mobile/cosmo-miner/App.tsx`.

### 3. Access-токен протухает — `refreshAccessToken` не используется

Функция `refreshAccessToken` есть в `cloudSave.ts`, но по коду не вызывается. После истечения access JWT запросы к API начинают получать 401; `fetchCloudSave` возвращает `null` без явной обработки для пользователя.

**Файл:** `mobile/cosmo-miner/src/game/cloudSave.ts`.

### 4. Гонки на `PUT /saves`

Два параллельных запроса могут оба прочитать один и тот же `existing.rev`, пройти проверку и выполнить upsert — победит последний запись. Для строгой сериализации нужны транзакция с блокировкой строки или атомарный `UPDATE … WHERE rev = $expected`.

**Файл:** `server/src/routes/saves.ts`.

### 5. Жёстко зашитый пароль в клиенте

`PasswordScreen` с константой пароля в исходниках — обходится при наличии билда или репозитория. Для закрытой беты может быть осознанным; для публичного релиза — риск.

**Файл:** `mobile/cosmo-miner/src/ui/PasswordScreen.tsx`.

## Средний приоритет

### 6. OAuth Google

- Используется endpoint **tokeninfo** (в `oauth.ts` отмечено как упрощение; для высокой нагрузки рекомендуют `google-auth-library`).
- Поле **`email_verified` не проверяется** — теоретический риск при сопоставлении по email без подтверждённого адреса.

**Файл:** `server/src/routes/oauth.ts`.

### 7. Сейв как произвольный JSON

Нет жёсткого лимита размера тела и серверной схемы для `data` — риск DoS и раздувания БД.

**Файл:** `server/src/routes/saves.ts`, `server/prisma/schema.prisma` (`UserSave.data` — Json).

### 8. IAP без серверной верификации

Кредиты начисляются на клиенте после завершения транзакции в сторе, без проверки чека на бэкенде — типичная слабость для реальной монетизации.

**Файл:** `mobile/cosmo-miner/src/services/iap.ts`.

### 9. Токены в AsyncStorage

Комментарий в коде верный: для продакшена предпочтительнее **SecureStore / Keychain**, чтобы усложнить кражу refresh-токена при компрометации устройства/бэкапа.

**Файл:** `mobile/cosmo-miner/src/game/cloudSave.ts`.

### 10. Инфраструктура HTTP API

В `server/src/index.ts`: нет CORS (может понадобиться для веб-сборки), нет security headers в духе helmet, порт слушания захардкожен. Для продакшена обычно: переменные окружения, TLS за reverse proxy, отдельные health/readiness при оркестрации.

**Файл:** `server/src/index.ts`.

### 11. Обработка ошибок в `authenticate`

В `jwt.ts` при ошибке verify вызывается `reply.send(err)`. Стоит убедиться, что в проде всегда отдаётся **401** и предсказуемое тело без лишних внутренних деталей.

**Файл:** `server/src/plugins/jwt.ts`.

## Низкий приоритет / сопровождение

### 12. Дублирование игровых данных

Помимо `packages/game-config`, в мобилке остаются крупные локальные таблицы (`RESEARCH.ts`, `ALIENS.ts` и т.д.). Риск **расхождения** с серверным `/config` при правках — нужна дисциплина или постепенная унификация.

### 13. Автотесты

В исходниках нет выделенных unit/integration тестов для auth / saves / oauth — регрессии по контракту ловятся вручную.

### 14. Remote config и кэш

`remoteConfig.ts` кэширует полный ответ `/config` в AsyncStorage; тип на клиенте узкий. При эволюции API клиент должен безопасно игнорировать неизвестные поля (частично уже через optional поля).

**Файл:** `mobile/cosmo-miner/src/game/remoteConfig.ts`.
