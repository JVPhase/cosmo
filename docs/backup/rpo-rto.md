# Cosmo — RPO/RTO и план восстановления

> База данных: PostgreSQL 16 (Docker `cosmo-postgres`, БД `cosmo_db`)  
> Дата: 2026-04-11

---

## 1. Целевые показатели

| Параметр | Значение | Обоснование |
|---|---|---|
| **RPO** (допустимая потеря данных) | **24 ч** | Один daily-дамп; критичные данные — purchases, grants, wallet |
| **RTO** (допустимое время простоя) | **30 мин** | Время восстановления дампа + рестарт стека |
| Хранение локально | 7 дней | Быстрый доступ при локальном сбое |
| Хранение удалённо | 30 дней | S3-совместимое хранилище / rsync |

> **Приоритет таблиц при частичном восстановлении:**
> 1. `User`, `Wallet`, `Purchase` — финансовые данные
> 2. `Grant`, `Inventory` — состояние инвентаря
> 3. `GameplaySave`, `UserSave` — прогресс игрока
> 4. `UserConsent` — юридические требования (GDPR / 152-ФЗ)
> 5. CRM-таблицы — бизнес-данные

---

## 2. Стратегия резервного копирования

```
Тип          Расписание        Хранение
─────────────────────────────────────────
Full dump    Ежедневно 02:00   Локально 7 д, S3 30 д
Schema-only  Ежедневно 02:15   Локально 30 д (для аудита миграций)
```

Инструмент: `pg_dump` через `docker exec` (не требует отдельного клиента).  
Формат: **custom** (`-Fc`) — сжатый, поддерживает параллельное восстановление.

```

S3 / rsync-target:
  s3://your-bucket/cosmo/backups/daily/
```

## 4. Восстановление — пошаговый план

### 4.1 Полное восстановление (DR)

| Шаг | Действие | Команда / файл |
|---|---|---|
| 1 | Поднять пустой PostgreSQL | `docker compose up -d postgres` |
| 2 | Убедиться, что БД доступна | `docker exec cosmo-postgres pg_isready` |
| 3 | Восстановить дамп | `scripts/restore.sh <путь_к_дампу>` |
| 4 | Проверить миграции | `cd server && npx prisma migrate deploy` |
| 5 | Поднять сервер | `docker compose up -d server` |
| 6 | Smoke-тест | `curl http://localhost:3001/health` |

Ожидаемое время: **15–30 мин** (зависит от размера БД).

### 4.2 Частичное восстановление (одна таблица)

```bash
pg_restore -Fc --data-only -t "Purchase" \
  -d postgresql://postgres:postgres@localhost:5432/cosmo_db \
  cosmo_db_20260411_020000.dump
```

### 4.3 Откат после неудачной миграции Prisma

```bash
# 1. Остановить сервер
docker compose stop server

# 2. Восстановить дамп (до миграции)
scripts/restore.sh /var/backups/cosmo/daily/cosmo_db_<TIMESTAMP>.dump

# 3. Запустить предыдущую версию образа
docker compose up -d server
```
